# 原神养成材料规划器

作者：Kumasuke120
状态：现行设计

## 1. 产品定位

原神养成材料规划器是离线优先的 Electron 桌面工具。用户选择角色天赋、武器突破或手动材料目标，填写库存，查看所需素材、3:1 基础合成、合成角色被动期望和最终缺口。

程序、用户资料和游戏资料包分离：

- 程序负责界面、计算、Profile、方案和受限的桌面能力。
- 游戏资料包负责角色、武器、材料、图标、培养曲线和合成角色被动。
- 用户可主动同步 Lunaris、导入或导出游戏资料、恢复内置资料；失败或取消不替换旧资料。
- 主流程不依赖网络，资料同步只由主进程在用户明确发起后执行。

## 2. 全局规则

- 完整类别名称为“角色天赋素材”和“武器突破素材”；紧凑 Tab 可简写为“角色天赋”和“武器突破”。
- 所有面向用户的“核算”统一使用“计算”。
- 中文游戏系列使用 `「」`，例如 `「风雅」系列`、`「蝶变」突破方案`。
- 中英文名称、日期、Tooltip 和图标说明随语言切换同步更新。
- 星级必须用可读的 `1★` 至 `5★` 文字表达，颜色只作辅助。
- 通知是无关闭按钮的自动提示，显示约 3.5 秒后消失。

## 3. 信息架构

左侧导航固定为：

1. 总览
2. 武器突破
3. 角色天赋
4. 手动计算
5. 设置

语言切换位于全局顶栏。设置包含“我的方案、游戏资料、关于”三个 Tab，不设置“常规”页。

## 4. 总览

总览标题下显示“选择培养目标，查看所需素材。”。

页面使用左右两列：

- 左列为“最近保存的方案”，显示最近五个方案和更新时间。
- 右列为“材料系列”，显示类别 Tab、材料条目和分页。
- 两列标题到第一项内容的垂直间距必须一致，第一行内容水平对齐。

材料系列按类别分页，每页固定 8 项。类别 Tab 为“角色天赋 / 武器突破”；中文系列显示 `「系列名」系列`，英文显示资料包定义的简洁专有名。点击材料系列进入手动计算，自动选中该类别和系列。

总览不显示游戏资料状态或导入导出操作。

## 5. 计算页

武器突破、角色天赋和手动计算使用相同的页面骨架：

1. 标题与右上角总体状态、方案操作。
2. 目标编辑区。
3. 材料计算表。
4. 页面底部的合成角色。

右上角是唯一的总体结果区：

- 已满足时显示“已满足”。
- 缺材料时显示“缺少素材”及按星级分列的彩色标签，例如 `2★ x39`、`3★ x12`。
- 不重复显示第二个总体状态或第二个保存入口。

材料表按资料包定义的 2/3/4/5 星材料列出库存、需求、基础合成后、被动期望和合成后可用。三个计算页调用同一计算引擎：先保留每个星级的直接需求，再仅将剩余的低星级材料按 `3 -> 1` 向上合成为相邻高星级材料，绝不允许高星级反向拆分。合成后数量可继续参与下一星级合成。

角色被动只产生整数材料：双倍产物为每轮 `floor(本轮合成次数 × 0.1)` 个目标星级材料；返还为每轮 `floor(本轮合成次数 × 0.25)` 个投入星级材料。返还材料回到当前星级后，只有累计到 3 个才进入下一轮合成和返还计算；不使用等比数列近似，也不会显示小数材料。

材料表仅显示一个“合成后可用”总计行，主数字为最终可用整数。每个星级固定显示绿色“合成 +N”；选中合成角色时固定显示紫色“被动 +N”，即使本轮整数估算为 `+0` 也不可省略。返还后形成的额外整次合成并入合成数量；两类来源均已包含在主数字内。材料表头的图标在鼠标悬浮或键盘聚焦时显示页面级预览浮层，包含放大图标、完整名称与星级；浮层不能被表格裁切。

### 5.1 角色天赋

目标区显示角色选择器和三行天赋：普通攻击、元素战技、元素爆发。每行固定显示“当前等级 / 目标等级”列。目标等级低于当前等级时显示校验提示，但仍允许保存方案。

角色选择器支持元素图标和 4/5 星两层筛选，结果按角色稳定 ID 数值降序显示。

### 5.2 武器突破

目标区显示武器、当前突破阶段和目标突破阶段。武器选择器支持武器类型图标和 1 至 5 星两层筛选。

武器结果按以下固定类型顺序分组：

1. 单手剑
2. 双手剑
3. 长柄武器
4. 弓
5. 法器

每个类型内部按稳定 ID 数值降序显示。

资料包保留 1 至 5 星武器。来源没有可验证突破关系或计算曲线的武器可浏览并明确显示“暂不支持突破计算”，但“保存方案”和“另存为”禁用，绝不伪造需求。

### 5.3 手动计算

用户选择“角色天赋 / 武器突破”类别、材料系列和各星级需求，再填写库存。计算表和合成角色规则与预设目标一致。

## 6. 选择器与 Tooltip

角色、武器和合成角色选择器均为居中弹层，拥有稳定的窗口高度；搜索、筛选和标题位置不会因筛选结果变少而移动。结果区域独立滚动。

角色与武器使用固定 112px 高的图标格，从顶部排列；结果不足一行或数行时，剩余区域留白，卡片不得被拉长。

角色、武器长名称使用页面级自定义 Tooltip：鼠标悬浮或键盘聚焦时显示完整当前语言名称。Tooltip 不位于可滚动列表内部，因此不会被首行、末行或滚动容器裁切，也不会制造额外滚动条。

元素筛选图标使用 Lunaris 缓存的：

`pyro.webp`、`hydro.webp`、`anemo.webp`、`electro.webp`、`dendro.webp`、`cryo.webp`、`geo.webp`。

武器类型筛选图标使用：

`sword.webp`、`claymore.webp`、`polearm.webp`、`bow.webp`、`catalyst.webp`。

默认未选中的筛选图标为黑色，选中状态为白色；每个图标都有当前语言的 `aria-label` 和自定义 Tooltip。

## 7. 合成角色

合成角色是可选附加项，位于材料表之后。页面仅保留“合成角色”一个入口标题。

合成角色弹层采用纵向列表：

- 左侧为固定 58px 头像。
- 右侧上方为角色名称，下方为完整固有天赋说明。
- 每项固定 76px 高，从顶部排列；角色数较少时不拉长行高。
- 仅显示对当前材料类别有效的角色。

首项为“不使用角色”，使用一个默认人形头像，说明为“无加成”。其高度、边框和选中状态与普通角色相同。页面未选中任何合成角色时，也显示“不使用角色 / 无加成”。

已选角色的被动效果计入材料表“被动期望”行。说明文案为：合成角色被动的加成已计入“被动期望”行；该值为期望结果，不代表单次合成的实际产出。

## 8. 方案

方案保存到 Profile，包含稳定目标 ID、当前与目标等级/阶段或手动需求、合成角色、名称、创建时间和更新时间；不保存概率性期望结果。

新建目标的“保存方案”打开应用内对话框，预填唯一的默认名称，用户仍可编辑：

- 武器：`「武器名」突破方案`
- 角色：`「角色名」天赋方案`
- 手动：`「材料系列名」手动计算方案`

打开“我的方案”中的已有方案后，计算页副标题显示：`当前方案：方案名称`。

- 主操作变为“保存更改”，直接覆盖当前方案，保留原方案 ID 与创建时间，更新目标、合成角色和更新时间。
- 名称在去除首尾空格、Unicode 规范化并忽略大小写后必须唯一；输入重复名称时显示校验提示且不能保存。导入和底层保存同样执行此校验。
- “另存为”打开命名对话框并建立独立新方案；若默认名称已存在，自动依次使用 ` (2)`、` (3)` 等后缀。
- 从导航进入新目标或从总览材料系列进入手动计算时，退出当前方案状态，重新走新建保存流程。
- 成功保存显示“已保存”或“方案已更新”的自动通知。

“我的方案”支持名称搜索、分页浏览、删除、导入和导出。列表按更新时间倒序，每页 10 项。

## 9. 游戏资料与设置

“游戏资料”使用结构化信息表展示：游戏资料版本、状态、Lunaris 来源链接、更新时间、角色数量、武器数量、角色天赋素材数量、武器突破素材数量和图标数量。

更新时间使用不含语言文字的本地数字格式：`YYYY-MM-DD HH:mm`。

用户可主动执行：同步 Lunaris、导入游戏资料、导出游戏资料、恢复内置资料。最近操作仅保存本机最近 5 条，成功操作必须带版本号，例如“已同步至游戏资料 7.0.54”。

关于页展示应用名称、从 `package.json` 读取的版本、作者和构建标识。构建标识来自 Git 短 commit；没有可用 commit 时显示 `local-uncommitted`。

## 10. 游戏资料包

生产内置包、导入导出包、测试示例包和界面翻译均使用 JSON。TypeScript 仅负责类型、Schema、加载和查询。

资料包包含：

- 角色：稳定 ID、中英文名、图标、元素、星级和天赋材料系列 ID。
- 武器：稳定 ID、中英文名、图标、类型、星级、突破材料系列 ID、逐阶段需求和计算状态。
- 材料系列：稳定 ID、类别、中英文系列名、按星级分组的材料及图标。
- 合成角色：稳定 ID、中英文名、头像、适用类别、被动策略和双语说明。

Lunaris 将初始武器 `1X101` 标记为 `QUALITY_GREEN` 时，适配器以稳定 ID 优先归类为 1 星；`1X201` 保持 2 星。

武器突破素材的中文系列名从来源共同前缀归一化，并去除末尾“的”“的一”或“之”。英文系列名使用按稳定来源材料 ID 维护的确定性映射，例如 `Boreal Wolf`、`Blazing Sacrificial Heart`、`Delirious`；不使用 AI 或不稳定的自然语言猜测。

同步仅在所有 JSON、关系、材料完整性、图标缓存和业务规则校验通过后原子安装。同步失败、取消或导入失败时，旧包继续有效。

## 11. 安全与持久化

Electron 保持：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`

渲染进程只通过类型化 preload API 调用受限能力，不能提交任意下载 URL 或文件路径。主进程拥有网络、文件选择、资料安装和外部链接打开权限。

`profile.json` 保存语言、库存、方案、最近方案和更新时间；不复制完整游戏资料包。游戏资料操作记录独立存放，只保留最近五条。

## 12. 验收标准

- 应用离线启动后可完成角色天赋、武器突破和手动计算。
- 总览材料系列按类别每页固定 8 项，两列内容对齐，中文系列使用 `「」`。
- 角色和武器选择器可打开、搜索、筛选；弹层稳定、卡片不拉伸、Tooltip 不裁切。
- 角色按 ID 降序；武器按固定类型顺序且类型内按 ID 降序。
- 合成角色行高固定，首项为“不使用角色 / 无加成”。
- 材料图标预览显示放大图、名称和星级。
- 三个计算页只显示一次总体状态和保存区，缺口按星级标签展示。
- 新建方案可编辑自动名称；打开的方案可覆盖保存或另存为，副标题显示当前方案。
- 不可计算武器不能保存；其余目标可保存。
- 设置中“我的方案”“游戏资料”“关于”职责明确，游戏资料更新时间为数字格式。
- 中英文切换同步更新界面、名称、状态、自动方案名和 Tooltip。
- 单元测试覆盖领域计算、资料适配、方案保存、选择器、分页、筛选、Tooltip、合成角色和翻译；类型检查与前端构建通过。
